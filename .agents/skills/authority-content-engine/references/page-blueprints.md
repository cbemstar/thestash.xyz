# Page Blueprints

Use the blueprint that matches search intent. Keep intros short and answer the decision question early.

## Comparison Blueprint

Best for: `X vs Y` and decision-stage evaluation.

Required sections:

1. Verdict by scenario (who should choose what)
2. Evaluation criteria table (5 to 8 criteria)
3. Side-by-side analysis per criterion
4. Tradeoffs and failure modes
5. Implementation friction (migration/setup)
6. Final recommendation by team profile
7. FAQ (3 to 6 high-intent questions)

## Alternatives Blueprint

Best for: users replacing or upgrading a known tool.

Required sections:

1. Why users seek alternatives (specific constraints)
2. Quick shortlist table (tool, best for, caveat)
3. Deep dives for top alternatives
4. Migration checklist from current tool
5. Cost/risk considerations (qualify uncertain data)
6. Recommendation paths by team maturity

## Best-for-Use-Case Blueprint

Best for: `best [type] for [audience/use-case]`.

Required sections:

1. Selection criteria and weighting
2. Ranked list with transparent reasoning
3. Best overall, best budget, best enterprise, best flexibility
4. When not to choose each option
5. 30-day implementation starter plan

## Workflow Guide Blueprint

Best for: implementation and process queries.

Required sections:

1. Prerequisites and assumptions
2. Architecture or workflow diagram description
3. Step-by-step setup
4. Validation checkpoints and failure recovery
5. Operational guardrails (security, quality, cost)
6. Production hardening checklist

## Collection Hub Blueprint

Best for: thematic landing pages that support cluster depth.

Required sections:

1. Category definition and scope boundary
2. Tool taxonomy (subcategories)
3. Featured picks by use-case
4. Comparison and alternatives jump links
5. Learning resources and implementation guides
6. Related cluster links

## Metadata Pattern

For every format, provide:

- 3 title options
- 1 slug recommendation
- 1 meta title (<= 60 characters)
- 1 meta description (<= 155 characters)
